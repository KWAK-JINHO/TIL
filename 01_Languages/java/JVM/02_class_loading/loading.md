Class Loading은 컴파일된 바이트코드(`class`)를 읽어와 JVM의 메모리 영역에 배치하는 첫 번째 단계이다.

# Class Loading의 주요 역할

1. 클래스의 정규화된 이름(Fully Qualified Class Name, ex: `com.example.User`)을 통해 정적 바이너리 데이터를 읽어온다.
2. 이 데이터를 기반으로 JVM이 관리할 클래스 메타데이터 구조를 생성하여 **Method Area**에 저장한다.
3. Heap 영역에 해당 클래스의 메타 데이터와 매핑되는 `java.lang.Class` 타입의 인스턴스를 생성한다. 
   - 개발자는 이 `Class` 객체를 통해 Method Area에 있는 클래스 구조 정보(메서드, 필드, 애너테이션 등)를 참조하거나, 리플렉션 API를 호출 할 수 있게 된다.

## Dynamic Loading

자바는 프로그램 시작 시 모든 클래스를 메모리에 올리지 않고, Runtime에 해당 클래스가 **처음으로 참조되는 시점**에 메모리에 올린다. 이를 동적 로딩이라 하며 두 가지 방식으로 나뉜다.

1. Load-time Dynamic Loading:
   - 하나의 클래스를 로드하는 과정에서 그 클래스가 참조하는 다른 클래스(부모 클래스, 참조 변수 등)를 연쇄적으로 로드하는 방식
2. Runtime Dynamic Loading:
   - 코드가 실행되기 전까지는 어떤 클래스를 참조할지 전혀 모르다가, 실행 시점의 조건문이나 `Class.forName("className")` 등을 통해 동적으로 클래스를 
끄집어 올리는 방식입니다.

## 3. 클래스 로더 시스템의 3가지 원칙

JVM이 클래스를 로딩할 때 안정성을 보장하기 위해 지키는 3가지 원칙

1. 위임 원칙 (Delegation Principle): 클래스 로딩 요청을 받으면 최상위 클래스 로더(Bootstrap)부터 하위로 내려오며 클래스를 검색한다.
2. 가시성 원칙 (Visibility Principle): 하위 클래스 로더는 상위 클래스 로더가 로드한 클래스를 볼 수 있지만, 반대로 상위 클래스 로더는 하위 클래스 로더가 로드한 클래스를 볼 수 없다. (이를 통해 보안 및 캡슐화를 유지한다.)
3. 유일성 원칙 (Uniqueness Principle): 하위 클래스 로더는 상위 클래스 로더가 이미 로드한 클래스를 중복해서 로드하지 않도록 보장하여 클래스의 유일성을 유지.
