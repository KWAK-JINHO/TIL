# Cookie & Session

- HTTP 프로토콜은 상태를 유지하지 않는 Stateless 특성을 가짐.
- 하지만 로그인 정보, 장바구니 등 사용자의 상태를 유지해야 하는 서비스가 필요해졌고, 이를 위해 쿠키와 세션이 도입됨.

## Cookie
- 정의: 서버가 클라이언트(브라우저)에 저장하는 작은 데이터 조각.
- 저장 위치: 클라이언트 메모리 또는 하드디스크.
- 특징:
  - 브라우저가 종료되어도 만료 시간이 남았다면 유지될 수 있음.
  - 요청 시마다 HTTP 헤더에 담겨 서버로 자동 전송됨.
  - 보안에 취약함 (중간에 탈취되거나 위변조 가능).
  - 도메인당 개수와 크기(약 4KB)에 제한이 있음.

## Session
- 정의: 사용자의 정보를 서버 측에서 관리하는 방식.
- 저장 위치: 서버의 메모리(In-memory) 또는 데이터베이스(Session DB/Redis).
- 특징:
  - 클라이언트에는 사용자 식별자(Session ID)만 발급함.
  - 쿠키보다 보안성이 높음 (실제 정보가 서버에 있기 때문).
  - 사용자가 많아질수록 서버 메모리 부하가 증가함.
  - 브라우저가 종료되면 기본적으로 세션이 만료됨.

## 쿠키와 세션의 동작 방식 (Session ID)
1. 클라이언트가 서버에 로그인 요청을 보냄.
2. 서버는 정보를 확인하고 고유한 Session ID를 생성함.
3. 서버는 응답 헤더(Set-Cookie)에 Session ID를 담아 보냄.
4. 클라이언트는 받은 Session ID를 쿠키에 저장함.
5. 이후 요청 시마다 쿠키에 담긴 Session ID를 함께 보냄.
6. 서버는 전달받은 Session ID로 서버 내 세션 저장소에서 사용자 정보를 조회함.

## 요약 및 차이점
- 핵심 차이: 정보가 어디에 저장되는가? (클라이언트 vs 서버)
- 보안성: 세션 > 쿠키.
- 속도: 쿠키 > 세션 (서버 조회가 필요 없으므로).
- 용도: 
  - 쿠키: 오늘 그만 보기 팝업, 쇼핑몰 비로그인 장바구니 등.
  - 세션: 로그인 정보, 개인정보가 포함된 민감한 데이터 등.
